## 本步骤实现的功能

- `GroupCommand`：把已有对象收入新 Group；
- `UngroupCommand`：解散嵌套 Group，子节点提升到原父级；
- `AddToCommand`：把对象移动到指定 Group 的最后一个子节点；
- `FrontCommand`：同级视觉置顶，移到列表末尾；
- `BackCommand`：同级视觉置底，移到列表开头；
- Group 和子图形的父级、Document 归属和子节点顺序同步维护；
- group、ungroup、addto、front、back 都是单独的 undo 单元；
- Group 和其后代不能同时参与 group；
- 容器不能移动到自己的后代；
- 顶层 Group 不能 ungroup；
- 层级操作失败时保持原树、对象集合和历史栈不变；
- 多个同级对象被摘出后，按原索引恢复，避免顺序反转。

当前顺序约定（2026-10-30 修订）：同级子节点按 SVG 绘制顺序排列，索引 0 在视觉最底层，最后一个索引在最上层。`front` 移到列表末尾，`back` 移到列表开头。分组时按原文档的先序遍历顺序排列选中对象；新 Group 放在遍历中第一个选中对象的原父级、原位置，跨父级分组也遵循这一约定。

步骤四没有实现 CLI 文本解析、`tree`/`show` 输出、SVG 读写和文件命令；这些仍属于后续步骤。

## 测试发现的问题及修正

- 初次实现分组撤销时，同级对象的摘除和恢复顺序导致顺序反转或索引越界，改为从后向前摘除、按原索引从前向后恢复。
- 提交前补测发现，选中对象在不同层级之间交错时，仅对同父级对象局部排序仍可能让原索引偏移。现统一按文档遍历的逆序摘除，保证每个父级都从后向前处理；新增用例验证 undo、redo 后再次 undo 均可恢复。
- 排序原先复用了插入位置的索引上界，允许索引等于同级数量，可能在摘除后才报错。现调整为只接受 `0..数量-1`，在修改树之前拒绝越界。
- 上述新增的 3 个边界用例在修正前均失败，修正后全部通过。

## 2026-10-30：验收口径修订

### 原因和决定

1. 原实现和测试将列表开头视为 front，但 SVG 后绘制的同级元素覆盖先绘制的元素。现明确 front/back 表示视觉置顶/置底，分别映射到列表末尾/开头；SVG 写出、读回及 tree 必须保持同一文档顺序。

原始实验文档 `phase_cli_1.md` 保留不变。上述解释和补充约定集中记录在 [acceptance-spec.md](./acceptance-spec.md)，并同步到测试草稿、实现计划和架构文档。

## 2026-10-30：移动、溢出及层级接口回归修复

### 问题与修复

| 问题 | 原有风险 | 当前处理 |
|---|---|---|
| 移动参数非法 | Rect/Circle/Ellipse/Text 先写入横坐标，再校验 dy，失败后留下不能撤销的修改 | Shape 统一校验输入，各图形计算待更新值，整个子树准备完成后才写入 |
| 运算溢出 | 输入有限但加法/乘法产生 Infinity，后续快照无法恢复 | 检查所有位置和尺寸的计算结果，出现非有限数即报 invalid-number；不写入、不截断 |
| Group 部分修改 | 后部或嵌套后代失败时，前部兄弟可能已经改变 | 准备阶段遍历全部后代；任何准备失败时不运行任何提交函数 |
| 已挂载 Group 绕过 Document | 传入 Document 引用即可直接插入重复对象、重复 ID，或摘除后留下归属不一致 | 移除公开 Group 方法的 Document 参数，已挂载 Group 的公开添加/插入/删除一律拒绝 |
| 直接改父级或归属 | 公开 setter 可改指针而不改树列表 | 移除 setParent/setDocumentOwner；父级、归属、子列表使用私有字段，内部符号入口只供领域类协作 |
| 脱离文档的树 ID 冲突 | 原检查仅覆盖当前 Group 子树，遗漏祖先和其他分支 | 从所在树的根检查全部已有 ID，加入前拒绝冲突 |
| 外部对象引用操作 Document | 删除时未先统一确认对象身份属于该文档 | 在删除前检查成员身份；跨文档对象和同 ID 的另一对象不能替代目标 |

数值仍使用 JavaScript number；本轮检查输入及结果是否有限，不引入任意精度计算，也不改变普通小数、负坐标和有限大数结果的合法性。

## 输入规则与补充决定

依据原文第 2、3、4.1 节实现下列规则。原文没有固定的细节在这里明确为项目决定。

- 空行、纯空白、去掉前导空白后以 `#` 开头的整行直接跳过。按用户要求，另支持引号外独立 `#` 引入行末注释：`#` 与前后内容用空白隔开，或位于行尾，例如 `move r1 10 0 # 向右移动`。颜色 `#4a90d9`、参数内的 `drawing#1.svg` 和引号内的 `#` 原样保留；行末的 `#注释` 不是独立标记，须写作 `# 注释`。
- 双引号包住一个完整参数，保留内部空白和空字符串。`create text` 的内容及 `set ... text` 的值必须带双引号。文字中的 `in`、`#` 不作语法解释。
- 引号内仅把 `\"` 和 `\\` 解码为双引号和单个反斜杠；其他反斜杠保留原样，不把 `\n`、`\t` 当作控制字符。普通路径如 `read "C:\new folder\drawing.svg"` 可直接使用；需要连续反斜杠时按此转义规则输入。
- 单引号不是引用语法；不支持把双引号片段与其他字符拼接为一个参数。未闭合引号在执行前报错。
- 仅在 create 参数的末尾识别未加引号的 `in <containerId>`。保留合法 ID `in`，例如 `create g in` 和 `create g child in in`。
- 数值接受带正负号的小数、整数和科学计数法，要求完整匹配且结果有限。空字符串、空白、十六进制、`NaN`、`Infinity`、`1foo` 和溢出值被拒绝。正尺寸、正缩放因子等业务规则继续由领域层校验。
- 按用户明确要求，`init` 只接受 0 或 2 个尺寸，语法为 `init [w h]`：无参数创建默认 800×600，双参数使用指定宽高；`init 400` 返回 `error: usage: init [w h]`。`canvas` 同样只接受 0 或 2 个尺寸。
- CLI 的 `group` 按 `<newGid> <id1> <id2>...` 要求至少两个目标；已有底层 GroupCommand 的单目标能力保留给程序调用。
- `help` 不需要当前文档，方便首次启动时查看语法；其他依赖文档的查询、编辑、undo/redo 仍返回原文的无文档错误。这是对原文“其他命令”表述的明确例外。
- 命令名、类型名和 ID 大小写敏感。没有新增 `exit` 命令，使用 EOF 退出。

## 输出、历史与失败原子性

REPL 启动回显原文的 `svg-editor 0.1 — type 'help' for commands`，随后显示 `svg> `。每行完成后继续显示提示符；单条业务错误不终止进程；EOF 正常退出。导入 main 模块不会启动 REPL。

成功摘要遵循原文示例，例如：

```text
rect#r1 created in g#scene
circle#c1 moved to (130,100)
circle#c1 moved back to (100,100)
text#title updated: text="My Diagram v2"
rect#box restored into g#markers
saved to demo.svg (5 elements)
warning: assigned id rect1 to unnamed <rect>
read other.svg (7 elements)
```

原文未固定的摘要也提供明确结果：Group/line 平移显示增量；scale undo 显示 `scale restored`；z-order undo 显示 `z-order restored`；撤销新增样式显示 `<unset>`。undo 和 redo 的摘要绑定实际 Command 对象，用 WeakMap 保存输出回调，读取恢复后的对象状态；不新增平行历史栈、不改变 Command 接口，也不在 CLI 重做领域逻辑。

tree 保持 Unicode 分支和原始文档顺序，图形标签与关键属性间固定两个空格，不复制示例中用于列对齐的不同填充宽度。show 输出父级 `svg` 或 `g#id`、完整几何、文字及显式设置的 fill/stroke/stroke-width；未显式设置的样式不伪造为属性。文字使用 JSON 引号/转义保持一行。

原文已规定的领域和文件错误保留完整消息。统一出口只加一个 `error:` 前缀，并把消息中的换行折叠为空格。项目新增的解析错误为：

| 场景 | 格式 |
|---|---|
| 未知命令 | `error: unknown command: <name>` |
| 参数过多/缺少 | `error: usage: <该命令语法>` |
| 非法数值 | `error: invalid number for <参数/属性名>` |
| 未闭合双引号 | `error: unterminated double quote` |
| 参数中段使用双引号/引号后拼接字符 | `error: quotes must enclose a whole argument` |
| 命令名带引号 | `error: command name must not be quoted` |
| text 内容没有双引号 | `error: text must be double-quoted` |

解析和参数错误发生在编辑执行前；业务失败继续依靠既有 Command/DocumentSession 的原子性。测试同时比较属性、树结构、对象身份、当前文档与路径，并保留原有 undo/redo 栈顶。read 只有全文成功后才输出 warning，后部非法 SVG 不会先打印部分成功信息。序列化或写入失败不清历史。

文档操作成功后仍遵守已确认的规则：清空两栈并禁止 undo/redo，下一条成功编辑开启新历史。canvas 查询、tree/show/help 不改变历史及禁用状态；失败编辑不能解禁。

## 架构与扩展边界

名字分派仍集中在两处：CommandRegistry 的命令 Map，以及 ShapeFactory 的类型构造和参数元数据。CLI 没有按 rect/circle 等名称新增 switch。

tree/show 所需的几何展示采用类型化 Visitor：Shape 声明 accept，每个具体类调用对应 visit 方法，CLI 的 ShapePresenter 实现格式化。接口位于 domain，反向引用 CLI/Node/XML 库的依赖没有引入。代价是未来增加内置图形时要更新 Visitor 接口和具体展示方法；这不是本阶段的插件协议，插件化工作继续留到后续阶段。

ShapeFactory 的参数元数据同时用于位置参数映射、CLI 数值/属性校验和 help，移除了工厂原来第二段位置参数 switch。领域对象仍负责白名单和业务值约束。S7 可继续评估注册表体积、重复代码及模块依赖；本步骤没有把完成 CLI 等同于最终质量评审完成。
